**当前约束：用户明确**

- 一个人开发。
- 发布平台为 Steam，中文与英文。
- 支持单机以及最多 8 人联机，希望房间人数上限可配置。
- 六个月不作为硬性发售截止，可继续投入，但总周期不超过三年。
- 设计方案与已批准的开发规范按职责维护，主文档保持少量、易维护。

第一版已采用包含房主的 1～8 人好友 PvE、房主保存世界，具体权限与代价见玩法文件。最终价格、总时长、发售日期和最低配置尚未确定。原稿 25～35 小时主线保留为原始愿景，本版先完成有明确用途的内容再实测时长，不通过空跑或重复刷取填满指标；此前在半年硬期限假设下提出的 2～4 小时范围不作为本版约束。

**第一版定位与内容边界**

《归流》围绕“返乡、调查、战斗、改变故乡”展开。玩家带着老师的信回到渡驿，与伙伴在一个手工构建、规则一致的幻想山谷中调查异常，理解历史责任，并与居民一起完成当前处置。

|---|---|---|
| 类型与世界 | 俯视角 2D Action RPG；一个渡驿据点、四个相连地区 | 通行规则见玩法，地区事件见剧情 |
| 战斗与能力 | 剑、大剑、长枪、弓；火、冰、雷；四种基础武器各有一个变体 | 玩法 |

| 内容预算 | 三个大型遭遇；八项中型探索，其中四项为武器工艺、四项为独立地方故事 | 玩法与剧情各维护所属部分 |
| 经济与家园 | 确定性探索奖励、有限个人金币、免费基础补给；事件和一次性组件形成公共家园 | 玩法 |

**原始设计思想**

> 一款以好奇心推动玩家前进的 2D 谜团开放世界 Action RPG。玩家在手工构建、规则一致的世界中探索、理解、战斗和获得能力，最终完成有始有终的冒险。

原始方向保留六个体验支柱：

| 支柱 | 在游戏中的作用 |
|---|---|
| 探索 | 看见值得调查的异常，选择自己的方向，发现世界的新部分 |
| 谜团 | 让玩家关心原因，收集证据并逐渐理解真相 |
| 战斗 | 提供挑战、紧张和技能表达；质量与变化优先 |
| 魔法与环境交互 | 让能力产生新的行动选择，并重新理解旧地点 |
| 剧情 | 让调查有持续的意义、人物有动机、最终有收束 |
| 家园与缓冲 | 在冒险之间提供整理、放松和归属感，服务主体验 |

希望玩家记住的是：“那是我自己发现的”“我终于看懂它了”“我想试试另一个地方”。持续游玩的吸引力是设计目标，目前没有本项目实测数据证明已经达成。

**从原稿保留的取舍原则**

1. 玩家能自主选择调查目标，游戏帮助保留必要信息。
2. 探索提供新发现，控制空跑和重复通行。
3. 成长主要来自发现、理解和行动，减少重复刷取。
4. 能力带来新做法，不能只体现为伤害增加。
5. 战斗注重质量、节奏和选择，不能靠堆数量填地图。
6. 装备具有身份和适用打法，减少同质数值垃圾。
7. 关键玩法有确定性获取途径，不被低概率掉落阻断。
8. 世界规则前后一致，反转应解释已建立的线索。
9. NPC 与环境共同呈现故事，让玩家有调查和推断空间。
10. 主线有完整结局，可选探索不否定已经完成的旅程。

不把大量每日农务、无限材料升级、海量随机词条、反复刷 Boss 或无意义跑腿作为主循环。家园、生态、装备和收集可以存在，但应能解释它们如何服务冒险。

**目标受众与尚未证明的判断**

当前受众假设：喜欢手工世界、调查秘密，愿意接受动作战斗和适量阅读的人；合作玩家还希望与朋友共同发现和成长。

原稿提到 Terraria/Core Keeper、Zelda/CrossCode、Monster Hunter、Stardew/Rune Factory 玩家作为参照。这些群体偏好不同，不能直接相加为市场规模，也不能假定其中所有人都愿意迁移。

“探索比奖励更能维持兴趣”“武器×魔法降低成本”“家园提高留存”“第一小时五个疑问最佳”均仍需证据或试玩验证。具体评论数据和它们支持的设计判断统一放在玩法文件中。

**体验冲突时的取舍**

| 冲突 | 第一版处理 |
|---|---|
| 神秘感与基本理解 | 教会操作、已知事实和失败原因，保留故事推断 |
| 战斗挑战与主线调查 | 保留物理打法、知识打法与合理绕行，提供战斗辅助；可选挑战承接更高操作要求 |
| 开放顺序与预设演出 | 承认提前发现与提前处理的结果，对白和后续行动随实际状态变化 |
| 合作自由与共同初见 | 提供集合提示、共享成长与个人阅读权；首次发现不能为所有迟到者重演 |
| 内容数量与完成质量 | 先兑现每段问题、行动、成长及完整收束，再依据制作与试玩结果评估扩充 |
| 家园与冒险节奏 | 家园承担准备、人物联系和旅途展示，不产生每日劳动或等待作物的主线门槛 |

**表现与情绪原则**

画面使用清楚轮廓和有限材质类别，使木、石、金属、浅水及导电结构能被辨认。当前模板资产不直接等于最终美术资源；保留生活痕迹与地域差异，魔法反馈同时承担异常、交互和战斗信息。

角色制作方向已确认为：以 PixelLab 外观参考建立有限分层素材并补全遮挡部分，使用 Godot 运行时骨骼，以刚性绑定为主，同体型共享动作，必要姿势辅以少量替换帧；武器与特效独立。保持风格化 2D 像素美术，PixelLab 使用 `128px` Sprite Size 与 `low top-down` 视角；生成选项与实际画布、可见高度分开记录。当前已有首个候选角色和两方向骨骼技术样板，完整八方向、美术质量与全自动制作仍未验收。先验证样板，再用两个不同外观核对动作复用与真实工时，之后决定外观规模；不把八人容量理解为必须制作八套独立人物。具体玩法规则在玩法文件，运行架构与实现见[角色系统开发规范](player/README.md)，分层制作、自动化与制作验收见[创建新角色流程与规范](player/character_creation.md)。

渡驿从返乡时的冷清，经历老师回来后的聚集、旧事公开后的关系裂痕，再呈现结局后的新生活。归属感由具体人物与变化承载，不能仅由家具数量推定。重要声音配视觉反馈，颜色配形状，减少队友非必要特效并优先保留敌人预兆；具体规则统一在玩法文件维护。

**添加内容时的判断**

每项新内容都说明：它能否增加好奇心，是否产生新的选择，会不会增加重复劳动，是否符合世界规则。只有功能名称、缺乏体验作用的内容，先留在所属文档的待讨论项，不扩成独立系统文档。

**第一版验收与制作顺序**

本版已有四地区代表事件、主要人物回应、成长与经济、合作并发和两种处置的设计基线。下一步以实际规格和验证完善这套基线，不把已经采用的方向继续写成尚无方案，也不把代表事件等同于完整地图、全部对白或已通过玩家测试。

| 阶段 | 需要达到的结果 |
|---|---|
| 系统样板 | 四武器与三法有可辨差异；保存、共享权益和最大人数基础同步成立 |
| 完整蓝湖 | 新玩家能提出问题、验证猜测、取得能力并改变世界；单机及合作的主要乱序能完成 |
| 完整冒险 | 四地区、奖励安排和两种处置走通，检查关键顺序与结局后可达性 |
| 发行验证 | 中英文、手柄、性能、断线恢复及长流程回归通过相应检查 |

这些是后续制作的验收顺序，不是本轮已完成的开发任务。功能正确与吸引力分开验证：能连上八人不等于八人都有参与，文本因果自洽不等于玩家会自愿继续。

**尚需确定或验证的边界**

- 每周实际投入、美术与音效的自制/购买/外包方式及预算尚未明确；用样板实做成本核算三年内的内容范围，不仅凭期限推算。
- 场景尺度、逐地点状态、完整对白、剩余动作参数和资源清单在所属文件内细化；已给数值保留为调参初值。
- 玩家对问题的理解、战斗选择、回访负担、双语体验及 1/2/4/8 人参与感均待本作实测，具体观察方法与证据在玩法文件。
- 最终发行名称、价格、时长、发售日和最低配置不由当前纸面设计直接承诺。
