# 玩法设计

《归流》第一版设计基线已获准写入。本文统一维护玩家行动、战斗、成长、探索通行、合作、奖励与验证规则；产品约束见[设计思想](/Users/ze/godot-project/godot-2d-topdown-template/docs/01_设计思想.md)，人物、历史、证据含义与结局正文见[剧情与世界观](/Users/ze/godot-project/godot-2d-topdown-template/docs/03_剧情与世界观.md)。

**状态与边界：** 这是获准记录的第一版设计，不代表功能已经实现、数值已经平衡或体验已经得到玩家验证。表内数值是调参初值。未给出的参数集中列在末尾，不用此前未采纳的讨论数字补齐，也不因写入文档自动开始游戏开发。

## 版本范围与核心循环

第一版采用剑、大剑、长枪、弓四类武器，每类包含基础形态和一个行为变体。每人携带两种不同武器，各选一种形态，并装备一个护符；没有固定职业。火、冰、雷作为本版三种法术，学会后均可随时选择。风、土、光保留在原始内容池，不纳入本版范围。

本版不设经验等级、装备 +N 强化、普通制造材料墙、普通箭矢库存或负重。能力、武器工艺和关键玩法确定性获得，可以免费试验与重新配置。无经验等级是本版取舍，不能追溯声称原稿禁止等级。

> 发现矛盾 → 自选调查方向 → 提出猜测 → 用观察、魔法、环境或战斗验证 → 获得答案和行动机会 → 改变世界 → 重新理解旧线索 → 选择下一个目标。

每段调查兑现一个具体问题。奖励可以是新做法、知识、人物关系、独特装备、捷径或永久变化，不要求每个秘密发装备。战斗提供变化和高潮，不用连续刷怪填充地图。目标是玩家自愿继续、愿意回来并能说明原因；不引入每日任务、错过惩罚或低概率核心掉落制造继续玩的压力。

## 操作、镜头与信息

每名玩家使用自己的俯视镜头，不以共享镜头把八个人绑在同一画面。没有独立跳跃键；梯子和短翻越属于有明确提示的场景交互，不能把不可读的高低差变成主要阻碍。

| 动作 | 键鼠默认 | 控制器默认 |
|---|---|---|
| 移动／瞄准 | WASD／鼠标 | 左摇杆／右摇杆 |
| 普通攻击 | 左键 | RT |
| 武器特殊动作 | 右键按住、释放 | LT 按住、释放 |
| 施放当前法术 | Q | RB |
| 开关武技注魔 | R | LB |
| 选择火／冰／雷 | 1／2／3 | 十字键左／上／右 |
| 切换两把出战武器 | Tab | Y |
| 闪避 | Space | A |
| 交互 | E | X |
| 饮药 | F | B |
| 地图／调查记录／装备 | M／J／I | View 打开后切换分页 |
| 设置／暂停 | Esc | Menu |
| 标点 | 可重绑，默认键待界面样板确定 | 十字键下 |

输入支持重绑定。法术选择、武器切换、直接施法和注魔分别有明确状态；注魔图标常驻，专注不足时显示未就绪，不能只依赖玩家记住按过哪个键。

单机打开地图、日志、装备和设置界面时可以暂停世界；联机个人阅读、查看地图和装备界面不暂停全队，也不赋予阅读无敌。普通对白和线索可个人阅读、回查，队友远处发现只提示地点和有新内容，正文由本人主动打开。界面应保留危险提示，安全阅读位置由关卡提供。

基础操作、资源、存档、重试、回返和已获得能力的用法直接说明。日志保存事实和来源，不自动把全部事实连成答案；个人帮助分三层：回顾相关事实、提示调查范围、提供明确帮助。提示不检查玩家是否把日志读满。

信息不能只靠颜色区分：材质、可交互对象、敌人预兆、受控保护期使用形状或图标，并提供视觉与声音提示。多人时优先显示敌人招式、危险位置、自己的目标与共享状态，降低队友特效遮挡；同一目标显示一套状态，不叠八套破甲或冻结反馈。中英文本分别检查，关键推断不依赖未经设计的单一语言双关。

## 角色创建、表现与动画复用

本节角色方案已由用户确认采用；制作方向更新为有限分层与 Godot 运行时骨骼。运行架构、资源协议与系统接入见[角色系统开发规范](player/README.md)，分层制作、自动化、制作差距与验收见[创建新角色流程与规范](player/character_creation.md)。当前已有首个候选角色和两方向骨骼技术样板，尚未完成完整角色、美术质量或全自动流程验收，也不代表八方向战斗或八人联机已经实现。

创建角色采用名字、外观预设与限定配色，没有固定职业或外观附带属性。首批可玩外观共用一种基础体型；用两个轮廓有明显差别的外观验证制作流程，不在本轮承诺首发外观数量。八名玩家可以使用相同预设，以名字、配色和队伍标记辨认，辨识不能只依靠颜色。名字与外观沿用、世界内进度隔离仍遵守下方合作规则。

创建只使用当前可用外观，本节不把有限经济中的三件可购买外观自动改成免费预设。三件外观的具体形式、解锁记录与跨世界沿用的映射仍需细化；复制外观信息不等于发放金币、装备或购买权益。

人物保持完整、清楚的视觉形象，制作时允许有限分层并补全遮挡区域，以运行时骨骼的刚性绑定为主，同体型共享动作库，少量特殊姿势使用替换帧。相同轮廓的限定换色可以共用贴图，不同发型或服装轮廓仍需制作分层外观并适配；八方向的透视、握持与前后遮挡仍需验证。Godot 运行时绑定的职责见[角色系统开发规范](player/README.md)，PixelLab 制作参考与自动化边界见[创建新角色流程与规范](player/character_creation.md)。

| 已确认原则 | 本版规则与成本边界 |
|---|---|
| 同体型统一规格 | 镜头角度、人物比例、像素密度、脚底原点、握持范围与基础明暗统一；画布大小和人物可见高度分开确定，最终像素规格通过地图样板验证 |
| 八方向表现 | 普通移动覆盖八个方向；每个动作按实际需要登记方向。固定场景交互不机械制作八套，战斗方向不能随意减少而破坏瞄准与命中可读性 |
| 镜像按动作审核 | 无武器移动可验证五方向加镜像；持武器动作先检查八方向，只有手性、服装、光照、握持与遮挡均适用才复用镜像 |
| 移动与瞄准分开 | 保留独立瞄准及弓蓄力半速移动。人物需要表现持弓前进、后退和侧移，普通 Run 不能代替；上、下肢动作组合与完整方向组合由样板落实 |
| 武器独立 | 同类同握持动作共用轨迹，不为每把剑重新设计人体动作；武器仍可能需要多个方向、姿态和双手适配，不能按每把一张 PNG 估算 |
| 行为变体可辨认 | 大剑横扫与直砸、枪突刺与回扫使用符合实际命中形状的表现；灰烬剑第三击有可读反馈，穿柳弓可复用姿势并延长蓄力保持 |
| 三元素独立 | 火、冰、雷共用人物施法动作，通过效果表达区别；不同武器的蓄力共用状态逻辑，不强行共用拉弓、举剑、施法身体姿势 |
| 统一动作时间 | 同一动作在各玩家外观上具有相同游戏时序；帧数与播放方式不能改变发力、取消、命中、饮药、救援和躲避窗口 |
| 按角色职责制作 | 玩家覆盖全部玩家能力；主要 NPC、环境人物只制作实际行为，艾妲足伤保留对应表现；兽、鸟、构装使用各自体型与行为模板 |

动作覆盖基础待机／移动／闪避；剑普攻／格挡／受挡／反击；大剑普攻／蓄力／横扫重击／直砸；枪普攻／架枪／突刺／回扫；弓快射／拉弓／保持／释放／蓄力移动；施法；受伤／饮药／倒地／救援／起身／死亡表现；实际需要的机关、梯子与短翻越交互。阶段可以共用动作段或保持姿势，不要求每个逻辑状态制作完整独立动画。Walk／Run 是资源用途，不因此增加冲刺输入、自由跳跃或游泳玩法；倒地不能按不可恢复死亡结算。

样板先验证少量方向的分层质量、跑步、挥剑及持弓移动，再扩展八方向与第二个外观。完整验收仍需核对两个外观的八向移动、剑格挡反击、弓蓄力移动、双手大剑、换武器与三元素，以及八实例同屏辨识。记录生成任务与额度变化、分层补画、绑定、方向适配及动作复用的实际成本，结果维护在角色开发规范中。八实例同屏只验证表现，不能代替下方要求的跨设备八人联机验证。

工具能力依据、旧逐帧候选与新骨骼样板的实际结果统一维护在[创建新角色流程与规范](player/character_creation.md)。共享动作不能免除分层补画和方向适配；A／B 外观复用、正式可用率与总工时收益仍待验证，不将图片帧数、MCP 调用次数或理论纹理大小直接当作计费与性能结论。

## 资源、动作承诺与武器

| 项目 | 第一版初值与规则 |
|---|---|
| 生命／体力／专注 | 基础上限各 100；护符影响另计，幅度待调参 |
| 体力恢复 | 停止消耗 0.6 秒后，每秒恢复 25；举盾／维持格挡和持续蓄力期间不恢复 |
| 专注恢复 | 停止使用魔法 1.2 秒后，每秒恢复 12；普通武器攻击不阻止恢复 |
| 普通移动与普通攻击 | 不消耗体力；普通箭矢无库存 |
| 闪避 | 消耗 20 体力；总动作 0.45 秒，其中 0.18 秒为躲避窗口 |
| 直接施法 | 消耗 20 专注 |
| 注魔武技 | 在物理武技成本之外，额外消耗 15 专注 |
| 初始治疗 | 3 次药瓶使用次数，标准配方每次恢复 45 生命；有效安全点免费补满 |

武器的初值只规定已确定部分，其他起手、收招、伤害和作用范围见末尾待细化表。

| 武器 | 普通攻击 | 特殊动作与成本 | 决策与代价 |
|---|---|---|---|
| 剑 | 12 伤害，约 0.35 秒一次 | 按住格挡；基础形态每次格挡冲击消耗 15 体力；成功格挡后可释放反击 | 近处防守、抓短窗口；承担贴身风险，体力耗尽不能继续稳定格挡 |
| 大剑 | 24 伤害，约 0.7 秒一次 | 完整蓄力 0.9 秒，重击 40 伤害，消耗 25 体力 | 抓长窗口、造成强冲击；起手和收招使打空与误判有代价 |
| 长枪 | 14 伤害，约 0.45 秒一次 | 架枪迎击正面突进，或主动释放突刺；特殊攻击 26 伤害，消耗 20 体力 | 管理距离和正面路线；侧面包围时需要换位 |
| 弓 | 快射 8 伤害 | 完整蓄力 0.9 秒，射击 28 伤害，消耗 15 体力；蓄力时移动速度减半 | 从远处打弱点和选择角度；近处受压与短窗口不利于完整蓄力 |

起手进入明确发力点之前，可以闪避取消；未释放的攻击或魔法不扣该次释放资源，闪避仍付体力。发力后扣除资源，打空也不退；攻击生效与收招前段承担动作代价，不能靠取消消除大剑等武器的风险。各动作具体发力点与可衔接时刻需在动画样板中确定。

注魔开启本身不收费。有效释放武技时使用当前元素并支付专注；专注不足则执行物理动作，界面显示未就绪。普通格挡本身不重复扣专注，剑通过反击释放元素。所有武器变体都有明确的特殊动作，注魔跟随该动作及实际命中形状，不因替换基础动作而丢失元素功能。

装备形态和护符在安全状态免费调整；交战中只切换已带的两种武器。改配不补生命、专注或已经用掉的药瓶，不把菜单切换变成恢复手段。

## 魔法、环境与十二种武器联动

| 法术 | 直接战斗作用 | 环境与探索作用及边界 |
|---|---|---|
| 火 | 点燃可燃目标，加热明确材质 | 烧干藤、点火、加热构件；不扩成任意燃烧整片地图的模拟 |
| 冰 | 冷却目标，满足条件时短暂冻结；冷却受热甲壳形成热裂 | 在可识别的浅水表面形成临时通路；不冻实整湖，不凭空增加缓冲容量 |
| 雷 | 沿真实导电关系传递，打断符合条件的动作 | 检查断路、启动局部完好装置；不能用个人施法永久替代山谷的大型持续供给 |

同类材质遵守一致规则。燃烧、受热、冷却、热裂、导电及保护期必须有可读反馈；不为单个谜题临时修改相同对象的反应。个人魔法与大型网络的能力边界遵守[已确认世界规则](/Users/ze/godot-project/godot-2d-topdown-template/docs/03_剧情与世界观.md)。

| 武器特殊动作 | 火 | 冰 | 雷 |
|---|---|---|---|
| 剑反击 | 反击命中使近处目标受热或燃烧 | 近身反击扇面冷却目标，为撤离或追击创造机会 | 成功防守后的反击释放电击，利用实际导电关系 |
| 大剑重击 | 完整蓄力命中燃烧目标时爆燃，耗尽该燃烧状态 | 对已冻结或脆裂目标碎冰，换取强冲击并结束相应冻结控制 | 从落点向实际导电对象放电 |
| 长枪迎击／突刺 | 沿狭窄命中路线加热目标 | 在枪距内冷却目标，帮助保持距离 | 穿刺后沿实际相连的导电目标传递 |
| 弓蓄力射击 | 把热量送到远处可见弱点或可燃构件 | 远程定点冷却，也可作用于符合规则的浅水表面 | 把放电起点送到箭矢实际命中的位置 |

十二格复用元素规则，差异来自动作、距离、命中形状、窗口和成本，不等于十二套独立技能树。剑冰是近身防守后的反击冷却；冰弓是承担蓄力风险的远程定点冷却，不只表现为换色伤害。

普通可冻结目标在短时间内受到三次冷却后冻结 0.8 秒，随后有 6 秒冻结保护；“短时间”的累计窗口尚待调参。大型敌人在符合失衡条件时失衡 1 秒，之后有 8 秒共享保护；冰、雷及相关强冲击不能由不同玩家分别重开控制计时。大型敌人的条件和强冲击累积参数仍需细化，不能把每次命中都当成失衡。

热裂只对明确可受热处理的甲壳成立。爆燃耗尽燃烧状态，碎冰结束冻结，不能无限重复结算同一状态。燃烧伤害、状态持续时间、冷却量、热裂收益、导电距离与目标数没有在本版设定初值，后续统一调参。

火可以融化临时冰面，但必须经过完整预警，不能让队友瞬间落水。自然融化同样预警；落水回到附近可站立岸边，不丢关键物品。永久回程桥不被火融掉。临时冰面尺寸、存在时间、预警长度与落水生命代价仍需界面和关卡样板确认。

## 普通行为与大型遭遇

普通战斗复用已描述遭遇中的基础行为，明确预兆与应对；行为表不等于新增同等数量的敌人或独立美术体系。

| 行为 | 可见预兆 | 玩家应对 |
|---|---|---|
| 扑击 | 压低身体、短叫、面向目标停顿 | 横向闪避、枪迎击，抓落地窗口 |
| 冲撞 | 刨地、直线对准后起跑 | 移到侧面，诱导撞上坚固障碍 |
| 正面护甲 | 正面甲片闭合，转身露出腹侧 | 绕侧、抓转身或热裂，不要求唯一破甲方法 |
| 远程瞄准 | 拉弓声、身体定住、瞄准反馈逐渐稳定 | 借遮挡、逼近或抢先打断 |
| 定点充能 | 导线发亮、连续提示音、构件展开 | 离开导电路径、打断或关闭供能支路 |

生物具有领地和退出范围，不是全部见人就攻击。图鉴通过观察记录行为、栖息、弱点、抗性和世界关联，不把主要战术信息锁在重复击杀数量后。完整天气、昼夜、月相模拟不纳入本版前置系统。

| 大型遭遇 | 单人基础生命 | 战斗预兆与阶段区别 | 合理绕过与不杀方式 |

永久变化同时更新通路和相关权益。退水后仍保留水痕、报警结构、遗迹和必要记录；漏读或晚到不会失去查证主要因果的全部机会。但已经消失的首次异常不能为每名后来者原样重演，日志补课不等于第一次推理体验。

### 战斗加入、救援与重试

普通战斗可以自由加入，不因新加入者增加敌人血量或数量。大型遭遇在开始时锁定实际入场名单与人数系数，新成员等待下一次尝试再进入该场战斗。

原参战成员因网络中断而重连时，保留断线前的本次状态，包括倒地状态，不补生命、药瓶或专注。场内被救起者可以继续；选择离场复起或补给的成员，本次不能再次入场，不能用出入安全点给场内队友循环输送满资源。离场或断线不降低本次人数系数，也不在战中清空或重置 Boss 血量；本次尝试结束后按新名单重开。

救援需要站定持续 3 秒，受击可打断；成功时消耗救援者一次药瓶次数，使目标恢复 30 生命。不额外触发净化或稳心配方效果，不补目标药瓶或专注，不设额外的单场被救次数上限，可用药瓶构成资源约束。无药不能开始救援；中断不扣药。同一目标本次起身只结算一次，并发救援不能重复扣药或重复恢复。倒地等待与安全复起的具体操作界面仍需细化。

失败在最近有效安全点重试，装备、金币、调查记录、关键能力与已完成永久机关保留。遭遇整体失败或全体撤离后，未完成战斗按重试重置，大型敌人恢复完整状态；不能反复送死累计削减血量。单名成员倒地不重置仍有队友参与的战斗。普通遭遇允许真正脱战后回安全点补给；大型遭遇按上文固定名单规则处理，不能把尚未结束的尝试当成已结束以免费补满再加入。

休息不把已解决主路重新填回同批敌人；可选重战由玩家主动发起，不重新发金币、核心工艺或唯一原物。

### 保存与恢复

永久世界变化、相应通路和权益一起保存；奖励的领取标记与到账一起保存，避免出现“标记领过但没有物品”或“到账后仍可再领”。退出时保存，运行中周期保存，并保留可恢复备份。

重连恢复该世界已有成员记录；新加入者进入有效安全位置，取得应有解锁和一次性权益。保存间隔、备份份数与异常恢复流程仍需实现规格，不承诺断电、崩溃或断线时进度零损失。

## 验证阶段与判断依据

写入设计不代表启动实现，也不代表已完成试玩。后续实施时分阶段验证，当前没有本作玩家测试结果：

1. **规则与状态样板**：验证直接输入、四武器与三法术、变体注魔、资源扣除、共享控制保护、救援、奖励一致性与最大人数的基础同步。
2. **蓝湖连贯体验**：把调查、实际设施条件、分流、能力回访、战斗替代方法和永久捷径串起来，检查不同顺序及晚加入。
3. **多地区连续体验**：检查多次调查后是否仍有新选择；覆盖单人、2、4、8 人及中文、英文新玩家，记录疲劳、等待和自然中断后的回访。
4. **发行验证**：完成中英文、手柄、性能、断线恢复和长流程回归，检查最终构建的实际表现。

样板和连续体验的实际制作时长、测试人数与招募安排需另行落实在本文件的验证记录中；不把此前建议的分钟数当成已证明的最佳节奏或正式主线承诺。

| 验证点 | 观察与记录 | 优先修改对象 |
|---|---|---|
| 对问题在意 | 玩家能否说出当前问题和下一步理由，是否主动调查 | 异常、人物利害、下一处线索 |
| 推理可兑现 | 能否提出并用动作检验猜测，分别说明因果 | 证据、反馈、是否最后全靠 NPC 告知 |
| 能力与成长 | 新能力是否使玩家想起旧地点，变体是否改变后续选择 | 教学、用途、奖励分布与遭遇 |
| 战斗表达 | 不同武器、元素和基础／变体是否在不同场合有理由使用 | 动作承诺、状态反馈、资源与敌人压力 |
| 回访值得 | 分开记录新发现与重复通行时间，询问回报是否值得 | 捷径、重试距离、奖励与现场变化 |
| 自愿继续 | 已兑现阶段答案且允许结束时，是否主动选择下个目标及原因 | 疲劳、悬念、奖励落空或新目标不足 |
| 愿意回来 | 中断后能否找回目标；区分自然回访和被邀请回访 | 日志、未读内容、阶段结束点 |
| 多人贡献 | 逐人记录发现、提出和验证过什么，结束后单独复述 | 一人包办、远处脱节、晚加入与等待 |
| 双语可理解 | 中文与英文玩家能否依靠相同证据完成推断 | 翻译、术语、图形与文字关系 |
| 状态与最大容量 | 房主加七名客机跨设备，覆盖断线、重连、名单变化、保存重入和同装置并发 | 状态一致性、资源恢复、奖励重复及进度阻塞 |

多人观察以局为单位，不把一局八名成员当作八次独立实验。不以在线久、走路多或开发者已知答案的通关证明投入。需要测试新谜团版本时，优先使用未知道答案的人。

功能通过要求包括：单人能完成主线；客机、迟到者不会因必要能力或通路权益卡住；重试不重复发奖励；保存重入恢复一致状态；最大容量确实经过跨设备测试。吸引力则依靠行为与访谈迭代，目前没有可信的外部统一比例可以直接作为通过线。

**玩家反馈与设计依据**

采样日期：2026-09-11，北京时间。149 条评论来自 Steam 官方接口：TUNIC 英语 20 负＋10 正；ANIMAL WELL 英语实际 19 负＋10 正；CrossCode 与 Drova 各英语 20 负＋10 正、简中 10 负＋5 正。按最近创建、Steam 购买、正负定额取样，逐条阅读并人工多标签编码；没有以主题关键词选评论。ANIMAL WELL 请求 20 条差评但仅返回 19，未为凑数补挑。

|---|---|---|
| 基础信息过隐 | TUNIC 英语差评 10/20；但英语好评 4/10 具体称赞发现与知识进展 | 保存事实、教会基础操作，同时保留推断空间 |
